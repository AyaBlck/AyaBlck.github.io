The question

A marketplace pays its pick-up point partners a commission on every item handed over to a customer: 5.5% of item value, capped at €2.50 per item.

Goods arrive at a pick-up point in postings — physical boxes. A box may hold one item or ten. The proposal is to move commission to posting grain: same percentage, but the cap applied once per box rather than once per item.

The finance question is what that costs or saves.

The analytical question is harder, and comes first: who pays for it? A cap that collapses from five charges to one affects a partner handling large consolidated boxes very differently from one handling single-item deliveries — and if the difference is large enough, an aggregate saving hides a retention risk in part of the network.

NoteData

Synthetic dataset of ~240,000 posting-item records across 850 pick-up locations and one calendar month. Data-quality defects — returns, superseded report versions, orders split across several boxes — were planted deliberately so the reconciliation steps have something real to catch. Generated by generate_data.py.

1. Where the volume is, and where the value is

Before modelling anything, one table decides how the rest of the analysis has to be built.

Channel mix: postings, value, and box composition 
mix = q("""
WITH clean AS (
    SELECT * FROM fct_posting_items
    WHERE record_status <> 'corrected'
      AND event_type NOT LIKE '%return%'
)
SELECT
    REPLACE(fulfilment_channel, '_', ' ')                  AS channel,
    ROUND(100.0 * COUNT(DISTINCT posting_id)
          / SUM(COUNT(DISTINCT posting_id)) OVER (), 1)    AS share_postings,
    ROUND(100.0 * SUM(item_value)
          / SUM(SUM(item_value)) OVER (), 1)               AS share_value,
    ROUND(COUNT(*) * 1.0 / COUNT(DISTINCT posting_id), 2)  AS items_per_posting,
    ROUND(SUM(item_value) / COUNT(DISTINCT posting_id), 2) AS avg_posting_value,
    ROUND(AVG(item_value), 2)                              AS avg_item_value
FROM clean
GROUP BY 1
ORDER BY share_value DESC
""")

mix.columns = ["Channel", "% postings", "% value",
               "Items / box", "Avg box €", "Avg item €"]

The two right-hand columns explain the mechanism. Average item value runs from €4.37 in the warehouse channel to €21.33 in merchant shipped, while items per box runs the opposite way, from 3.6 down to 1.5. Cheap goods travel together; expensive goods travel alone.

ImportantWhat this means for the model

The cap is hit by box value, not item count. So the channels most exposed are those with the highest average posting value — merchant shipped and cross border, not warehouse.

Item count matters only at the edge: a box with one item cannot change at all, since per-item and per-posting are identical there.

Quantified in section 3.

Restated rows are corrected partner reports — counting both versions inflates volume. Return rows are negative-signed mirrors — counting them as handovers inflates it again. And 18.8% of orders arrive as more than one box, so order grain is not a substitute for box grain.

Item grain to posting grain 
con.execute("""
CREATE OR REPLACE VIEW posting_grain AS
WITH clean AS (
    SELECT * FROM fct_posting_items
    WHERE record_status <> 'corrected'          -- drop restated reports
),
signed AS (
    SELECT
        posting_id, pickup_point_id, fulfilment_channel,
        CASE WHEN event_type LIKE '%return%' THEN -1 ELSE 1 END AS sign,
        item_value, item_commission
    FROM clean
)
SELECT
    posting_id,
    any_value(pickup_point_id)    AS pickup_point_id,
    any_value(fulfilment_channel) AS fulfilment_channel,
    SUM(item_value)               AS posting_value,
    SUM(item_commission)          AS commission_current,
    SUM(sign)                     AS items_net
FROM signed
GROUP BY posting_id
HAVING SUM(sign) > 0            -- a fully returned box earns no commission
   AND SUM(item_value) > 0
""")
Reconciling the re-aggregation 
recon = q("""
WITH clean AS (
    SELECT * FROM fct_posting_items WHERE record_status <> 'corrected'
),
p AS (
    SELECT posting_id,
           SUM(item_value) AS v,
           SUM(CASE WHEN event_type LIKE '%return%' THEN -1 ELSE 1 END) AS n
    FROM clean GROUP BY posting_id
),
src      AS (SELECT COUNT(*) c, SUM(v) v FROM p),
orphan   AS (SELECT COUNT(*) c, SUM(v) v FROM p WHERE posting_id LIKE 'O9%'),
returned AS (SELECT COUNT(*) c, SUM(v) v FROM p
             WHERE posting_id NOT LIKE 'O9%' AND n <= 0),
final    AS (SELECT COUNT(*) c, SUM(posting_value) v FROM posting_grain)

SELECT 1 AS ord, 'Source: restated rows removed' AS step,
       src.c AS boxes, ROUND(src.v) AS val FROM src
UNION ALL SELECT 2, 'Less: returns with no handover in period',
       -orphan.c, -ROUND(orphan.v) FROM orphan
UNION ALL SELECT 3, 'Less: fully returned boxes',
       -returned.c, -ROUND(returned.v) FROM returned
UNION ALL SELECT 4, 'Posting grain, ready to model',
       final.c, ROUND(final.v) FROM final
ORDER BY ord
""").drop(columns=["ord"])

recon.columns = ["Step", "Boxes", "Value €"]
recon

1 Less: returns with no handover in period -180 1325.0
2 Less: fully returned boxes -491 0.0
3 Posting grain, ready to model 71978 1317098.0

The €1,325 movement is entirely 180 returns whose original handover sits outside the period, plus 491 fully returned boxes correctly earning nothing.

An unexplained 0.1% would be a worse result than an explained one.

WarningThe aggregate hides the spread

The platform pays out 5.2% less. But the impact per partner runs from 0% to −14%, and 125 of 850 pick-up points lose more than 8% of their commission income.

Those are partners handling high-value goods in small boxes — the cross border and merchant shipped channels. A saving delivered by concentrating the loss on a tenth of the network is a retention question, not just a cost question.

TipFindings

Commission falls 5.2% — from 4.83% to 4.58% of goods value, or €0.29 to €0.28 per item handed over. Roughly €3,300 a month at current volumes.

The saving is structural, not a rate cut. The rate and the cap are unchanged. It comes entirely from a box of several items no longer being capped several times.

A box of one item is unaffected — per-item and per-posting are identical there. 19% of boxes fall in this group and contribute nothing to the saving.

The cost lands unevenly. Cross border and merchant shipped absorb ~9% each against warehouse’s 3.7%, and 125 of 850 partners lose more than 8% of their income.

WarningRecommendation
  1. Proceed — the saving is real and comes from removing a duplication in how the cap is applied, not from paying partners a lower rate.
  2. Model the 125 exposed partners individually before launch. A network average of −4.7% is not what they will experience.
  3. Consider a transition floor for partners worse than −8%, funded from the saving. It costs a fraction of €3,300 a month and removes the retention risk.
  4. Confirm the billing system can attach commission at posting level. The current logic prices per item; posting-level pricing needs the discount allocation moved from item to box.
  5. Track realised versus modelled for the first two months. Box composition shifts with promotions, and the saving moves with it.

Method notes

Synthetic data throughout — no production data was used. DuckDB over parquet for the SQL, pandas and seaborn for modelling and charts, Quarto for the write-up.

Limitations: one month, so seasonality in box composition is untested; partners are assumed not to change behaviour in response to the new schedule; the model prices the change on today’s channel mix, which will drift.

```{python}
sns.histplot(pp["pct"], bins=40, color="#99f0a2", ax=ax)
ax.axvline(pp["pct"].median(), color="black", ls="--", lw=1,
           label=f"median {pp['pct'].median():.1f}%")
ax.axvline(-8, color="#c44e52", ls=":", lw=1.5, label="−8% threshold")
ax.set_xlabel("Change in commission earned (%)")
ax.set_ylabel("Pick-up points")
ax.legend(frameon=False)
for s in ["top", "right"]:
    ax.spines[s].set_visible(False)
plt.tight_layout()
plt.show()
```

::: {.callout-warning}
## The aggregate hides the spread

The platform pays out 5.2% less. But the impact per partner runs from **0% to
−14%**, and **125 of 850 pick-up points** lose more than 8% of their commission
income.

Those are partners handling high-value goods in small boxes — the cross border and
merchant shipped channels. A saving delivered by concentrating the loss on a
tenth of the network is a retention question, not just a cost question.
:::

## 4. The result

```{python}
#| label: business-result
#| code-summary: "Effect on the two metrics that matter"
r = q("""
SELECT SUM(commission_current)  AS cur,
       SUM(commission_proposed) AS prop,
       SUM(delta)               AS d,
       SUM(posting_value)       AS val,
       SUM(items_net)           AS n_items
FROM modelled
""").iloc[0]

cur, prop, d = float(r.cur), float(r.prop), float(r.d)
val, n = float(r.val), float(r.n_items)

pd.DataFrame([
    ["Commission, % of goods value",
     f"{100*cur/val:.2f}%", f"{100*prop/val:.2f}%", f"{100*d/val:+.2f} pp"],
    ["Cost per item",
     f"€{cur/n:.3f}", f"€{prop/n:.3f}", f"{d/n:+.3f}"],
    ["Total commission, month",
     f"€{cur:,.0f}", f"€{prop:,.0f}", f"{d:+,.0f} ({100*(prop/cur-1):+.1f}%)"],
], columns=["", "Now", "After", "Change"])
```

::: {.callout-tip}
## Findings

**Commission falls 5.2%** — from 4.83% to 4.58% of goods value, or €0.29 to €0.28
per item handed over. Roughly **€3,300 a month** at current volumes.

**The saving is structural, not a rate cut.** The rate and the cap are unchanged.
It comes entirely from a box of several items no longer being capped several times.

**A box of one item is unaffected** — per-item and per-posting are identical there.
19% of boxes fall in this group and contribute nothing to the saving.

**The cost lands unevenly.** Cross border and merchant shipped absorb ~9% each
against warehouse's 3.7%, and 125 of 850 partners lose more than 8% of their income.
:::

::: {.callout-warning}
## Recommendation

1. **Proceed** — the saving is real and comes from removing a duplication in how
   the cap is applied, not from paying partners a lower rate.
2. **Model the 125 exposed partners individually** before launch. A network average
   of −4.7% is not what they will experience.
3. **Consider a transition floor** for partners worse than −8%, funded from the
   saving. It costs a fraction of €3,300 a month and removes the retention risk.
4. **Confirm the billing system can attach commission at posting level.** The current
   logic prices per item; posting-level pricing needs the discount allocation moved
   from item to box.
5. **Track realised versus modelled** for the first two months. Box composition
   shifts with promotions, and the saving moves with it.
:::

## Method notes

Synthetic data throughout — no production data was used. DuckDB over parquet for the
SQL, pandas and seaborn for modelling and charts, Quarto for the write-up.

Limitations: one month, so seasonality in box composition is untested; partners are
assumed not to change behaviour in response to the new schedule; the model prices the
change on today's channel mix, which will drift.
